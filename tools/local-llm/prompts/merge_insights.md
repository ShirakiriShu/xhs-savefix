# 阶段2 · 汇总结构化 prompt

## 模板

```
你是产品调研负责人。以下是助理对各批小红书评论的归纳清单(同类主题可能重复)。
请归纳成去重后的洞察主题列表。

输出严格 JSON 数组(元素必须是对象),每个对象:
{"topic":"主题(≤12字)","type":"痛点|需求|竞品口碑","count":评论条数,
 "heat":点赞合计,"typical":"最有代表性的评论原文(≤80字)","who":"该评论用户",
 "advice":"产品建议(≤60字)","priority":"P0|P1|P2"}

优先级:P0=评论多或点赞高(👍≥5)且可直接指导决策;P1=信号明确证据中等;P2=少量提及观察即可。
要求:
- topic 去重合并(如"订阅费贵"和"月费太坑"是一个主题)
- typical 必须是原文摘录,不许改写
- count/heat 如实统计自清单
- 只输出 JSON 数组,不要其他内容

归纳清单:
{各批清单文本}
```

## 关键坑(详见 ../PITFALLS.md)

- 输出必须是**数组**。曾出现返回 `{"0":{...},"1":{...}}` 字典形态 → 宿主已做兼容,但尽量直接输出数组
- num_predict 必须 ≥2000,否则 JSON 截断导致解析失败
